# rt/idl - the hg message definitions: Unitree's generated code (reference) and our reconstructed IDL

Unitree's SDK does not ship the hg `.idl` files: it ships the CycloneDDS C++ code generated from them. These are
byte-identical copies of that generated code and of the SDK's CRC routine, fetched 10 Oct 2026 for v3 session 2.
`rt/include/r1rt/hg_msgs.hpp` takes its field order and types from them (plain structs, the CRC image);
`rt/src/crc32.cpp` ports `crc32_core` from `crc.h`.

**Our IDL (`src/unitree/idl/hg/*.idl`) is reconstructed from those headers and proven**: CycloneDDS 0.10.2's idlc
(`-x final`, built by `build_cyclonedds.sh`) regenerates all eight headers byte for byte, except the 9-line banner and
the include-guard name - including the XTypes type-map / type-info blobs, i.e. the type identifiers DDS peers match
(test `HgDds.GeneratedTypesEqualUnitrees`, built with `-DR1RT_WITH_CYCLONEDDS=ON`). Types are `@final` (idlc's
default, = Unitree's: struct flag IS_FINAL in their type objects), `octet` for the uint8 fields (TK_BYTE in their
type objects), `unsigned long` / `short` / `float`, unbounded sequences in HandCmd_ / HandState_.
